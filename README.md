# Харнесс

Учебный харнесс для LLM-агента на Python: минимальная программная обвязка, которая превращает языковую модель из генератора текста в агента, способного самостоятельно работать с файлами, командной строкой и браузером.

Проект написан, чтобы разобраться, как харнесс устроен изнутри. Весь код — один файл [harness.py](harness.py) с подробными комментариями на русском, рядом лежат автотесты [test_harness.py](test_harness.py), примеры навыков и учебный MCP-сервер. Готовые агентные фреймворки намеренно не используются: цикл агента, исполнение инструментов и управление контекстом написаны вручную.

> Это тестовый проект для изучения, а не инструмент для рабочих задач. Ограничения перечислены в разделе [«Безопасность»](#безопасность) и [«Ограничения»](#ограничения).

## Что такое харнесс

Языковая модель умеет одно: получить текст и вернуть текст. Она не может прочитать файл, запустить команду или открыть сайт, и она ничего не помнит между запросами.

Харнесс — это всё, что находится вокруг модели и даёт ей эти способности:

| Часть | Что даёт модели | Где в коде |
|---|---|---|
| Инструменты | «Руки»: список действий, которые модель может попросить выполнить | классы-наследники `Tool` |
| Исполнитель | Реальное выполнение действий и граница безопасности | `execute_tool`, `permit` |
| Контекст | Память в пределах сессии: история сообщений | класс `Context` |
| Цикл агента | Возможность делать много шагов подряд, глядя на результаты | `run_turn` |

Ключевая мысль: модель никогда ничего не выполняет сама. Она лишь возвращает текст вида «вызови `write_file` с такими-то аргументами». Решает, выполнять ли это и как, код харнесса.

## Возможности

- Читает, создаёт и перезаписывает файлы в рабочей папке.
- Работает с кодом: ищет по проекту, читает файлы по частям, правит точечно, запускает Python-файлы, показывает и откатывает изменения через git.
- Может работать в любой папке проекта, а не только в своей песочнице.
- Запускает shell-команды и фоновые процессы — например, поднимает веб-сервер и открывает его в браузере.
- Может запускать команды в системной песочнице macOS: без сети и с записью только в рабочую папку.
- Ищет информацию в интернете.
- Откатывает свои правки по команде `/undo` и показывает diff перед изменением файлов.
- Подключает внешние инструменты по протоколу MCP.
- Читает навыки — готовые инструкции для типовых работ — и выполняет хуки пользователя.
- Работает без диалога: одна задача из командной строки, итог в JSON.
- Использует дешёвую модель там, где сильная не нужна.
- Управляет браузером: открывает страницы, читает их, кликает по элементам, заполняет поля.
- Сам планирует многошаговые задачи и исправляет свои ошибки: результат каждого действия, включая ошибку, возвращается модели.
- Видит страницы: делает скриншот и смотрит на него, когда текста недостаточно.
- Помнит разговор, записывает важное в заметки и умеет продолжить прошлую сессию после перезапуска.
- Читает правила проекта из файла `AGENT.md`.
- Ведёт список задач и отмечает выполненное.
- Сначала показывает план и ждёт одобрения, если попросить.
- Поручает подзадачи субагентам, которые работают одновременно, каждый в своём контексте.
- Спрашивает разрешение на опасные действия по настраиваемым правилам.
- Останавливается по Ctrl+C, не теряя разговор.
- Печатает ответ по мере генерации, а не после паузы.
- Сжимает начало разговора, когда контекст становится слишком большим.
- Считает токены и деньги и останавливается при исчерпании бюджета.
- Пишет полный журнал каждой сессии в файл.
- Демо-режим показывает работу цикла без обращения к модели и без ключа.

## Быстрый старт

Нужны Python 3.10 или новее и ключ API [x.ai](https://console.x.ai/).

1. Склонировать репозиторий и перейти в папку:

   ```bash
   git clone https://github.com/cybertest-jpg/harness.git
   cd harness
   ```

2. Создать окружение и поставить зависимости:

   ```bash
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   ```

3. Скачать браузер Chromium для Playwright (около 100 МБ, один раз):

   ```bash
   .venv/bin/python -m playwright install chromium
   ```

4. Создать рядом со скриптом файл `.env` с ключом:

   ```
   XAI_API_KEY=ваш_ключ
   ```

   Файл `.env` внесён в `.gitignore` и в репозиторий не попадает.

5. Запустить:

   ```bash
   .venv/bin/python harness.py
   ```

В PyCharm достаточно выбрать интерпретатором проекта `.venv` из папки проекта и запустить `harness.py`.

## Режимы запуска

| Команда | Что происходит |
|---|---|
| `python harness.py` | Диалог с живой моделью. Окно браузера видно. |
| `python harness.py --headless` | То же, но браузер работает без окна. |
| `python harness.py --dir ПУТЬ` | Рабочей папкой становится указанный проект, а не `workspace/`. |
| `python harness.py --resume` | Продолжает последний сохранённый разговор. |
| `python harness.py --budget 1` | Агент останавливается, когда сессия израсходует 1 доллар. |
| `python harness.py --sandbox` | Команды агента выполняются в песочнице macOS. |
| `python harness.py --model grok-4.3 --effort low` | Другая модель и глубина рассуждений основного агента. |
| `python harness.py -p "задача"` | Одна задача без диалога; итог печатается в stdout. |
| `... -p "задача" --json` | То же, но итог — JSON с результатом, токенами и стоимостью. |
| `... -p "задача" --allow run_python,run_shell` | Разрешает перечисленные инструменты: без диалога спросить некого. |
| `python harness.py --demo` | Ответы «модели» записаны заранее, инструменты выполняются по-настоящему. Ключ и сеть не нужны. |

Параметры можно сочетать, например `--headless --dir ~/Projects/shop`.

Выход из диалога — пустая строка. Ctrl+C во время работы агента прерывает текущий ход, а не программу; Ctrl+C в строке ввода завершает её.

Команды в диалоге:

| Команда | Что делает |
|---|---|
| `/plan ЗАДАЧА` | Агент изучает задачу только инструментами чтения и показывает план; выполняет его после вашего `y` |
| `/compact` | Сжимает контекст вручную, не дожидаясь порога |
| `/undo` | Возвращает файлы к состоянию до последнего хода, в котором агент что-то менял |
| `/cost` | Показывает расход токенов и денег за сессию |

Когда агент просит разрешение на действие, ответов три: `y` — разрешить один раз, `a` — разрешать этот инструмент до конца сессии, любой другой — отказать.

Тесты запускаются без ключа и сети:

```bash
.venv/bin/python -m unittest -v
```

Демо-режим полезен, чтобы увидеть цикл в чистом виде: подставная модель просит показать папку, создаёт файл, читает его и пробует выйти за пределы песочницы — и получает отказ.

## Примеры задач

Файлы и команды:

```
Напиши скрипт на Python, который считает числа Фибоначчи, запусти его и покажи результат
```

```
Посмотри, что есть в папке, и опиши каждый файл
```

Код (запуск с `--dir` на папку проекта):

```
Тест test_cart.py падает. Найди причину, исправь её точечно, убедись, что тест проходит, и покажи git diff
```

```
Найди все места, где вызывается функция total, и перечисли их
```

Браузер:

```
Открой ru.wikipedia.org, найди через поиск статью «Фобос (спутник)» и скажи, в каком году его открыли
```

```
Открой news.ycombinator.com и перечисли пять верхних заголовков
```

Так выглядит работа агента в терминале:

```
вы: Открой ru.wikipedia.org, найди статью «Фобос (спутник)» и скажи, в каком году его открыли
  [шаг 1] browser_open({"url":"https://ru.wikipedia.org"})
    → Адрес: https://ru.wikipedia.org/wiki/...
  [шаг 2] browser_type({"element":4,"text":"Фобос (спутник)","submit":true})
    → Адрес: https://ru.wikipedia.org/wiki/Фобос

агент: Фобос открыли в 1877 году.
```

Строки `[шаг N]` — вызовы инструментов, которые попросила модель; строки со стрелкой — начало результата, который харнесс вернул ей обратно.

## Как это устроено

### Цикл агента

```
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
  история сообщений ──► модель ──► попросила инструменты? ──нет──► ответ пользователю
                                          │
                                          да
                                          ▼
                            харнесс выполняет инструменты
                                          │
                                          ▼
                          результаты дописываются в историю
```

Функция `run_turn` обрабатывает один запрос пользователя:

1. Если контекст превысил порог, сжимает его. Затем отправляет модели всю историю сообщений и описания инструментов.
2. Дописывает ответ модели в историю.
3. Если модель не попросила инструменты, ход закончен.
4. Иначе выполняет каждый вызов, дописывает результаты в историю и возвращается к шагу 1.

Предохранитель `MAX_STEPS` обрывает цикл после 20 шагов, чтобы агент не мог крутиться бесконечно.

### Контекст

API не хранит состояние: модель ничего не помнит между запросами. Поэтому харнесс сам ведёт список `messages` в объекте `Context` и каждый раз отправляет его целиком. Там же хранится размер контекста в токенах по данным последнего ответа API. В списке четыре вида сообщений:

| Роль | Содержимое |
|---|---|
| `system` | Системный промпт: кто агент, где работает, какие правила |
| `user` | Запрос человека |
| `assistant` | Ответ модели: текст и/или вызовы инструментов |
| `tool` | Результат одного вызова, привязанный к нему по `tool_call_id` |

### Инструменты на Pydantic

Каждый инструмент — класс [Pydantic](https://docs.pydantic.dev/). Из одного класса получаются три вещи:

- описание для модели — docstring класса и `description` полей;
- JSON-схема аргументов — её строит `model_json_schema()`;
- проверка аргументов, когда модель присылает вызов, — `model_validate_json()`.

Схема, которую видит модель, и проверка в коде берутся из одного источника и не могут разойтись.

### Ошибки — это тоже результат

Ошибка инструмента не роняет программу. Она возвращается модели обычным текстом, и модель сама решает, что делать: исправить аргументы, попробовать иначе или сообщить пользователю. Ошибки проверки аргументов указывают конкретное поле, например `content: Field required`.

### Инструменты для кода

Трёх файловых инструментов для работы с кодом мало: чтобы что-то найти, агент читал бы файлы подряд, а ради одной строки переписывал бы файл целиком. Отдельные инструменты дают ему цикл программиста: найти → прочитать кусок → поправить точечно → запустить → посмотреть, что изменилось.

- **Поиск.** `search` ищет по регулярному выражению и возвращает строки вида `файл:строка: текст`; `find_files` ищет файлы по шаблону имени. Служебные папки (`.git`, `.venv`, `node_modules` и подобные) пропускаются.
- **Чтение по частям.** `read_file` отдаёт строки с номерами и принимает диапазон. Номера связывают его с поиском: совпадение на строке 240 — читаем строки 220–260.
- **Точечная правка.** `edit_file` заменяет фрагмент `old_text` на `new_text`. Фрагмент обязан встречаться в файле ровно один раз: модель не видит файл, а помнит его по прошлому чтению, и требование уникальности не даёт ей поправить не то место. Если фрагмент не найден или встречается несколько раз, модель получает ошибку и уточняет.
- **Запуск.** `run_python` запускает `.py`-файл из рабочей папки без подтверждения человеком, чтобы цикл «написал — запустил — исправил» шёл быстро.
- **Git.** `git_status` и `git_diff` показывают, что изменилось с последнего коммита; `git_restore` откатывает файл и требует подтверждения, потому что правки при этом пропадают.

Результат любого инструмента обрезается до `OUTPUT_LIMIT` символов: один неудачный вызов с огромным выводом не должен занять весь контекст.

### Браузер: состояние и снимки

Браузерные инструменты отличаются от файловых двумя вещами.

**Состояние.** Браузер запускается при первом обращении и живёт до выхода из программы. Клик и ввод работают с той страницей, которую открыл предыдущий вызов. Это состояние хранит объект `BROWSER`.

**Снимок вместо страницы.** Страница может весить сотни тысяч символов, и отдавать её модели целиком нельзя. Вместо HTML модель получает снимок:

```
Адрес: https://example.com/
Заголовок: Example Domain
--- Текст (символы 0–917 из 917) ---
This domain is for use in documentation examples...
--- Элементы ---
[1] a «Learn more»
```

Чтобы составить список элементов, харнесс выполняет внутри страницы небольшой скрипт: он находит видимые ссылки, кнопки и поля, помечает каждый атрибутом `data-harness-id` и возвращает их список. Модель называет номер, харнесс находит элемент по этому атрибуту. После каждого действия нумерация строится заново.

Если текст страницы длиннее лимита, в снимке указано, с каким смещением вызвать `browser_read`, чтобы читать дальше.

### Откат правок

Перед тем как `write_file`, `edit_file` или `git_restore` изменят файл, харнесс запоминает его прежнее содержимое — по одной точке отката на ход. Команда `/undo` возвращает все файлы, затронутые за ход агентом и его субагентами, и удаляет созданные. Повторный `/undo` откатывает предыдущий ход. Git для этого не нужен.

После отката агенту дописывается пометка, какие файлы возвращены, иначе он считал бы, что его правки на месте.

Точки отката живут в памяти до конца запуска. Изменения, сделанные командами через `run_shell` и `run_python`, харнесс не видит и откатить не может.

### Просмотр правки перед применением

Когда инструменту правки задано правило `ask`, человеку показывается не JSON с аргументами, а diff: что было и что станет, удалённое красным, добавленное зелёным. При запуске с `--dir` это правило включается для `write_file` и `edit_file` автоматически: в настоящем проекте каждая правка идёт через ваш ответ. В собственной папке `workspace/` правки по-прежнему применяются без вопросов.

### Песочница для команд

Проверка путей защищает только файловые инструменты; запущенная команда ею не ограничена. Параметр `--sandbox` оборачивает `run_shell`, `run_python` и `process_start` в системную песочницу macOS (`sandbox-exec`) с такими правилами:

- сеть закрыта, кроме `localhost` — чтобы работали локальные серверы;
- запись разрешена только в рабочую папку и временные каталоги;
- чтение запрещено для `~/.ssh`, `~/.aws`, `~/.gnupg`, связки ключей, а также для `.env`, журналов, сессий и заметок самого харнесса.

В песочнице скрипт не может навредить за пределами рабочей папки, поэтому `run_python` с `--sandbox` выполняется без вопроса. Браузер и MCP-серверы в песочницу не входят. На Linux и Windows параметр не работает.

### Фоновые процессы

`run_shell` ждёт завершения команды, поэтому веб-сервер через него не запустить. `process_start` запускает команду и сразу возвращает управление; отдельный поток складывает её вывод в память харнесса. `process_output` отдаёт вывод, накопившийся с прошлого чтения, и состояние процесса, `process_stop` останавливает его вместе с дочерними процессами. При выходе из харнесса все фоновые процессы гасятся.

### Поиск в интернете

Инструмент `web_search` — это отдельный запрос к API x.ai со встроенным у провайдера инструментом поиска. Харнесс получает готовый краткий ответ и список источников; чтобы прочитать источник целиком, агент открывает его в браузере. Поиск идёт на дешёвой модели и входит в общий расход сессии.

### Выбор модели по задаче

Не всякой работе нужна самая сильная модель. В харнессе три роли:

| Роль | Модель по умолчанию | Глубина рассуждений |
|---|---|---|
| Основной агент | `grok-4.7` | `high` |
| Субагенты | `grok-4.3` | `low` |
| Сжатие контекста и поиск | `grok-4.3` | `low` |

`grok-4.3` у x.ai стоит примерно втрое дешевле `grok-4.7`. Модель и глубину рассуждений основного агента меняют параметры `--model` и `--effort`, остальное — константы в начале файла.

### Навыки

Навык — это файл `skills/<имя>.md` с инструкцией «как делать такую-то работу»; первая строка файла служит описанием. В системный промпт попадают только имена и описания, а полный текст агент читает инструментом `use_skill`, когда берётся за такую работу. Поэтому навыков может быть много, а контекст они почти не занимают — в отличие от `AGENT.md`, который загружается целиком.

В репозитории два примера: `code-review` и `bug-fix`.

### Хуки

Хук — команда пользователя, которую харнесс запускает до или после вызова инструмента. Просьбу в промпте модель может не выполнить, а хук срабатывает всегда. Хуки задаются файлом `hooks.json` рядом со скриптом:

```json
[
  {"when": "after", "tool": "edit_file", "command": "ruff check ."},
  {"when": "before", "tool": "run_shell", "command": "python check_command.py"}
]
```

Команда получает на стандартный ввод JSON с именем инструмента, аргументами и, для `after`, результатом. Хук `before` с ненулевым кодом выхода отменяет вызов, и его вывод уходит модели как причина. Вывод хука `after` дописывается к результату инструмента. `"tool": "*"` означает любой инструмент.

### MCP: внешние инструменты

MCP (Model Context Protocol) — открытый протокол, по которому агенты подключают инструменты, написанные кем-то другим. Сервер — отдельная программа; харнесс запускает её и обменивается с ней сообщениями JSON-RPC через стандартный ввод и вывод. Клиент написан вручную, без библиотек, и использует три запроса: `initialize`, `tools/list` и `tools/call`.

Серверы перечисляются в `mcp.json` рядом со скриптом:

```json
{"servers": {"demo": {"command": "python3", "args": ["examples/mcp_demo_server.py"]}}}
```

Инструменты сервера появляются у агента под именами вида `mcp__demo__word_count`. Их схему аргументов сервер даёт готовой, Pydantic здесь не участвует. По умолчанию каждый вызов чужого инструмента требует вашего разрешения: харнесс не знает, что тот делает.

Чтобы попробовать, скопируйте `mcp.example.json` в `mcp.json` — подключится учебный сервер из `examples/` с двумя инструментами. Он же показывает, как устроен сервер изнутри.

### Неинтерактивный режим

С параметром `-p` харнесс выполняет одну задачу и завершается. Ход агента печатается в stderr, а в stdout попадает только итог, чтобы его можно было передать другой программе:

```bash
.venv/bin/python harness.py -p "Сколько строк в notes.txt?" --json
```

```json
{"ok": true, "result": "В notes.txt 3 строки.", "error": null, "requests": 2,
 "input_tokens": 5120, "output_tokens": 31, "cost_usd": 0.0093, "session_file": "..."}
```

Код возврата 0 означает, что агент довёл ход до конца; 1 — что харнесс остановил его по лимиту шагов, бюджету или из-за ошибки API. Спросить разрешение в этом режиме не у кого, поэтому инструменты с правилом `ask` получают отказ, если не перечислены в `--allow`.

### Разрешения

У каждого инструмента одно из трёх правил: `allow` — выполнять, `ask` — спросить человека, `deny` — запретить. Проверка стоит в одном месте — в `execute_tool`, между проверкой аргументов и запуском, — а не разбросана по инструментам.

По умолчанию разрешение спрашивается у шести своих инструментов и у всех инструментов MCP:

| Инструмент | Почему |
|---|---|
| `run_shell` | Произвольная команда на машине |
| `run_python` | Произвольный код на машине |
| `process_start` | Произвольная команда, которая остаётся работать |
| `git_restore` | Безвозвратно стирает правки |
| `browser_click` | Может отправить форму |
| `browser_type` | Вводит данные на сайте |

Остальные выполняются без вопросов. Два режима запуска меняют правила: `--dir` добавляет вопрос для `write_file` и `edit_file`, `--sandbox` снимает его с `run_python`. Последнее слово — за файлом `permissions.json` рядом со скриптом:

```json
{"browser_click": "allow", "run_shell": "deny", "write_file": "ask"}
```

Отказ возвращается модели обычным текстом результата, и она решает, как поступить дальше. Ответ «всегда» действует до конца запуска и на субагентов тоже.

### Прерывание по Ctrl+C

Ctrl+C во время хода останавливает агента, а программа и разговор остаются. Сложность в том, что история может оборваться между вызовом инструмента и его результатом, а такую историю API не примет. Функция `repair_history` закрывает недостающие результаты заглушками «Прервано пользователем», после чего агенту дописывается пометка о прерывании — на следующий вопрос он ответит, зная, что успел сделать.

Параллельные субагенты останавливаются через общий флаг `CANCEL`: каждый проверяет его перед следующим шагом.

### Режим плана

Команда `/plan ЗАДАЧА` запускает ход, в котором модели показаны только инструменты чтения (`PLAN_TOOLS`): пишущих она просто не видит, а если всё же назовёт — исполнитель откажет. Агент изучает задачу и предлагает план. После вашего `y` следующий ход идёт уже с полным набором инструментов.

### Список задач

Инструмент `todo` принимает список шагов целиком с состоянием каждого: ожидает, в работе, выполнен. Список хранит харнесс, а не история сообщений, поэтому он переживает сжатие контекста: после сжатия точный список подкладывается агенту заново, а не в пересказе.

### Файл инструкций проекта

Если в рабочей папке лежит `AGENT.md`, его содержимое (до 8000 символов) добавляется в системный промпт при старте. Туда пишут правила проекта: как запускать тесты, какой стиль кода, чего не трогать. В отличие от памяти, этот файл пишет человек, и он привязан к проекту, а не к харнессу.

### Зрение

Текстовый снимок не передаёт картинки, графики и вёрстку. Инструмент `browser_screenshot` делает скриншот видимой части страницы. Результат инструмента в API — всегда текст, поэтому картинка уходит модели отдельным сообщением сразу после результатов шага. Изображение стоит много токенов, поэтому в контексте хранится только последний скриншот: предыдущие харнесс заменяет текстовой пометкой.

### Продолжение сессии

После каждого хода история сообщений и список задач сохраняются в `sessions/<дата>_<время>.json`. Запуск с `--resume` загружает последний файл и продолжает разговор. Системный промпт при этом берётся свежий — заметки и `AGENT.md` могли измениться. Журнал для продолжения не годится: он рассказывает человеку, что происходило, а здесь нужен точный список сообщений, который можно снова отправить модели.

### Учёт стоимости

После каждого хода печатается расход: токены на входе и выходе и сумма в долларах за ход и за сессию. API x.ai сообщает точную стоимость каждого запроса в поле `cost_in_usd_ticks` (10 миллиардов «тиков» в долларе), поэтому таблица цен харнессу не нужна. У других провайдеров этого поля нет — тогда считаются только токены. В сумму входят запросы субагентов и запросы на сжатие.

Параметр `--budget` задаёт лимит на сессию: агент проверяет его перед каждым обращением к модели и останавливается, когда лимит исчерпан.

### Автотесты

В `test_harness.py` — 89 тестов на стандартном `unittest`. Модель подменяется сценарием: тест задаёт, что «ответит модель», и проверяет, какие инструменты харнесс вызвал и какую историю собрал. Тесты не ходят в сеть и идут около пяти секунд. Проверяются цикл, склейка потоковых фрагментов, проверка аргументов, границы рабочей папки, инструменты для кода, разрешения, режим плана, список задач, сжатие, восстановление истории после прерывания, скриншоты, сохранение сессий, учёт стоимости, изоляция контекстов субагентов, откат правок, показ diff, хуки, навыки, фоновые процессы, выбор модели, неинтерактивный режим и MCP — на настоящем учебном сервере. Тесты песочницы запускают настоящий `sandbox-exec` и на других системах пропускаются.

Браузер, поиск в интернете и настоящая модель в тестах не участвуют — их поведение проверяется только вручную.

### Журнал сессии

В терминале видны только первые 200 символов каждого результата. В журнал пишется всё целиком. Каждый запуск создаёт файл `logs/<дата>_<время>.jsonl`, по одной записи JSON на строку:

| Событие | Что записано |
|---|---|
| `session_start` | Модель, были ли загружены заметки |
| `user` | Запрос человека |
| `model` | Текст ответа, вызовы инструментов, размер контекста и ответа в токенах |
| `tool` | Имя инструмента, аргументы и полный результат |
| `subagent_start` | Задача, переданная субагенту |
| `compact` | Сколько сообщений заменено и текст изложения |
| `image` | Что модели отправлен скриншот, и его размер (сама картинка в журнал не пишется) |
| `interrupt` | Ход прерван пользователем |

В записях `model` и `tool` поле `agent` показывает, кто действовал: основной агент или субагент. По журналу можно разобрать, почему агент поступил так, а не иначе, и как рос контекст.

### Потоковая выдача

Запрос к модели идёт с `stream=True`: ответ приходит кусочками, и функция `stream_reply` печатает текст сразу. Вызовы инструментов тоже приходят по частям — сначала идентификатор и имя, потом JSON аргументов фрагмент за фрагментом; харнесс склеивает их по номеру вызова. Расход токенов приходит в последнем кусочке.

### Память между запусками

Состоит из двух половин:

- Инструмент `remember` дописывает строку в файл `memory.md`. Что стоит запомнить, решает сам агент.
- При старте функция `system_prompt` подкладывает содержимое `memory.md` в системный промпт, поэтому новая сессия начинается уже с этими знаниями.

Файл можно читать и править вручную; удалить заметку можно только так. В репозиторий он не входит.

### Сжатие контекста

История растёт с каждым шагом, а окно модели конечно. Когда контекст превышает `COMPACT_AT_TOKENS`, функция `compact` просит модель кратко изложить начало разговора и заменяет его этим изложением. Последние `KEEP_RECENT` сообщений остаются как есть.

Резать историю можно не в любом месте: результат инструмента нельзя отрывать от вызова, который его запросил, иначе API отклонит запрос. Поэтому граница сдвигается назад до сообщения модели.

Цена сжатия — потеря деталей. После него агент помнит изложение, а не исходные сообщения, и при повторных сжатиях изложение пересказывается снова. В проверке с искусственно заниженным порогом агент после пяти сжатий подряд уже не смог назвать первое поручение разговора.

### Субагенты

Инструмент `delegate` принимает от одной до четырёх подзадач и для каждой запускает тот же цикл `run_turn` с чистым контекстом: свой системный промпт и одна задача. Всё, что субагент прочитал по дороге, остаётся в его контексте и исчезает вместе с ним; основной агент получает только итоговый текст. Так экономится контекст основного агента.

Подзадачи выполняются одновременно, каждая в своём потоке. Отсюда три следствия:

- **Браузер у каждого свой.** Playwright привязывает браузер к потоку, в котором тот создан, поэтому каждый субагент открывает собственный и закрывает его по завершении.
- **Вывод — целыми строками.** Основной агент печатает ответ потоком, а субагенты пишут в терминал только целые строки со своей меткой, иначе текст перемешался бы.
- **Вопросы человеку — по одному.** Запросы разрешений от разных субагентов выстраиваются в очередь.

Файлы у субагентов общие. Инструментов `delegate`, `remember` и `todo` у них нет: первый — чтобы субагенты не порождали друг друга без конца.

### Демо-режим

Класс `ScriptedClient` подменяет клиента API: возвращает заранее записанные ответы в том же потоковом формате, что и настоящая модель. На нём же построены автотесты. Цикл и инструменты при этом работают по-настоящему. Так можно проверять харнесс без затрат и без сети.

## Как добавить свой инструмент

1. Написать класс-наследник `Tool`: docstring — описание для модели, поля — аргументы, `run()` — действие, возвращающее строку.

   ```python
   class WordCount(Tool):
       """Посчитать количество слов в текстовом файле."""

       path: str = Field(description="Относительный путь к файлу")

       def run(self) -> str:
           words = safe_path(self.path).read_text(encoding="utf-8").split()
           return f"слов: {len(words)}"
   ```

2. Зарегистрировать его в словаре `REGISTRY`:

   ```python
   REGISTRY = {
       ...
       "word_count": WordCount,
   }
   ```

Больше ничего менять не нужно: схема для модели и проверка аргументов появятся сами.

| `SKILLS_DIR` | `skills/` рядом со скриптом | Папка навыков |

| `COMPACT_AT_TOKENS` | `40000` | Размер контекста, при котором включается сжатие |
| `KEEP_RECENT` | `6` | Сколько последних сообщений сжатие не трогает |
| `BASE_PROMPT` | — | Системный промпт основного агента |
| `SUBAGENT_PROMPT` | — | Системный промпт субагента |
| `COMPACT_PROMPT` | — | Указание модели, как сжимать разговор |
| `PLAN_NOTE` | — | Указание модели для режима плана |

Ключ API читается из переменной окружения `XAI_API_KEY` или из файла `.env`.

Поскольку API x.ai совместимо с форматом OpenAI, для перехода на другого совместимого провайдера нужно поменять `BASE_URL`, ключ и все три модели. Поиск в интернете и точная стоимость запросов завязаны на x.ai и у другого провайдера работать не будут.

## Безопасность

Что сделано:

- **Песочница для файлов.** Все инструменты, принимающие путь, работают только внутри рабочей папки; попытка выйти через `../` отклоняется.
- **Разрешения на опасные действия.** Shell-команды, запуск Python, откат файлов, клики и ввод в браузере по умолчанию выполняются только после вашего ответа. Правила настраиваются, инструмент можно запретить совсем.
- **Режим плана.** Позволяет увидеть, что агент собирается делать, до того, как он что-либо изменит.
- **Песочница.** С `--sandbox` команды агента лишены сети и записи за пределами рабочей папки и не могут прочитать ключи.
- **Откат.** `/undo` возвращает файлы к состоянию до хода.
- **Показ правок.** С `--dir` каждая правка файла показывается diff-ом и ждёт вашего ответа.
- **Хуки.** Позволяют навязать собственную проверку любому инструменту.
- **Только веб-адреса.** `browser_open` принимает лишь `http://` и `https://`, чтобы нельзя было открыть `file:///...` в обход песочницы.
- **Строгие аргументы.** Незнакомые или неверные по типу аргументы отклоняются до выполнения.
- **Лимиты.** Не больше 20 шагов на запрос; необязательный бюджет на сессию в долларах.
- **Потолок результата.** Вывод любого инструмента обрезается, чтобы не переполнить контекст.
- **Правило в промпте.** Агенту сказано считать текст веб-страниц данными, а не указаниями.

Чего это не даёт:

- **Без `--sandbox` разрешённое действие не изолировано.** Проверка путей защищает только файловые инструменты. Команда или скрипт, которым вы ответили `y`, могут обратиться к чему угодно на машине. Читайте, что именно запускается.
- **Песочница не закрывает чтение.** Запрещён только перечисленный список секретов; остальные файлы на диске команда прочитать может. Отправить их наружу она не сможет — сеть закрыта, — но содержимое попадёт в контекст и уйдёт провайдеру модели.
- **MCP-серверы и хуки работают вне песочницы и без ограничений.** Сервер — чужая программа с вашими правами, а описания его инструментов попадают в промпт. Подключайте только те серверы, которым доверяете.
- **Навыки — часть промпта.** Файл в `skills/` влияет на поведение агента так же, как `AGENT.md`.
- **Ответ «всегда» снимает защиту до конца сессии.** После `a` на `run_shell` агент выполняет любые команды без вопросов.
- **Отказ не останавливает поиск обходных путей.** В проверке модель, получив отказ на `run_python`, тут же попросила то же самое через `run_shell`. Разрешение она спросила, но расчёт на то, что вы читаете каждый запрос.
- **В `workspace/` правки файлов не подтверждаются.** Вопрос с diff включается только при `--dir`. Откат `/undo` действует до конца запуска, поэтому в настоящем проекте всё равно стоит работать под git.
- **Поиск отправляет запрос провайдеру.** Формулировку запроса составляет агент, и в неё может попасть содержимое вашего проекта.
- **Открытие страниц не подтверждается.** `browser_open` может обратиться к любому адресу, в том числе с данными из вашего проекта в строке запроса.
- **Защита от инъекций через страницы — только правило в промпте.** Это снижает риск, но не гарантирует, что вредоносная страница не повлияет на поведение агента.
- **Содержимое уходит провайдеру.** Всё, что агент читает — файлы, вывод команд, текст страниц, скриншоты, — отправляется в API x.ai как часть контекста.
- **Журнал и сессии хранят всё открытым текстом.** В `logs/` и `sessions/` попадает полное содержимое прочитанных файлов и страниц и вывод команд. Папки в репозиторий не входят, но лежат на диске.
- **Заметки и `AGENT.md` влияют на все будущие сессии.** Агент может дописать заметку или изменить `AGENT.md` в рабочей папке под влиянием вредоносной страницы, и это окажется в системном промпте следующих запусков. Время от времени просматривайте оба файла.

## Ограничения

- Сжатие теряет детали, и при повторных сжатиях потери накапливаются.
- Порог сжатия задан константой и не привязан к настоящему размеру окна модели.
- Агент не может удалять и исправлять свои заметки, только дописывать.
- `--resume` продолжает только последнюю сессию; выбрать более раннюю нельзя.
- `/undo` не видит изменений, сделанных командами, и не переживает перезапуск.
- Песочница работает только на macOS; `sandbox-exec` Apple считает устаревшим, хотя он по-прежнему поставляется с системой.
- Клиент MCP поддерживает только серверы со связью через стандартный ввод-вывод и только инструменты — без ресурсов, подсказок и серверов по HTTP. С серверами сторонних авторов он не проверялся, только с учебным.
- Вывод фонового процесса хранится в памяти целиком и не ограничен.
- Один поисковый запрос заметно дороже обычного шага и может стоить несколько центов: провайдер сам читает найденные страницы.
- В неинтерактивном режиме код возврата говорит только о том, что ход завершён, а не о том, что задача решена правильно.
- Прерывание по Ctrl+C не мгновенное для субагентов: каждый доводит до конца текущий запрос к модели.
- Параллельные субагенты не защищены от одновременной правки одного файла.
- Каждый субагент запускает собственный браузер — это медленно и расходует память.
- Бюджет проверяется перед запросом, а не во время него, поэтому последний запрос может немного превысить лимит.
- Точная стоимость известна только для x.ai; у других провайдеров считаются одни токены.
- Скриншот снимает только видимую часть страницы; прокрутки нет.
- `run_python` запускает только Python и использует интерпретатор самого харнесса, а не окружение целевого проекта; `pytest` в него не установлен.
- Агент не умеет коммитить: `git_status`, `git_diff` и `git_restore` — это просмотр и откат. `git_restore` не удаляет новые файлы, которых ещё нет в git.
- Поиск пропускает файлы больше 1 МБ и файлы не в UTF-8; `find_files` не понимает фигурные скобки в шаблоне.
- Браузер не видит содержимое `iframe`, не скроллит, не выбирает из выпадающих списков и не загружает файлы.
- На странице нумеруются только первые 60 интерактивных элементов.
- Сайты с капчей и защитой от ботов агент не пройдёт.
- Тексты ошибок проверки аргументов — на английском, как их выдаёт Pydantic.
- Автотесты не покрывают браузер и работу с настоящей моделью.
